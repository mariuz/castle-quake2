# CLAUDE.md

Working notes for developers and AI agents on Castle Quake 2: a Quake 2 port to Castle Game Engine (CGE) in Object Pascal (FPC). Sibling of `castle-quake1`. Read `docs/ARCHITECTURE.md` for full architectural details; user-facing docs are `README.md` and `docs/FEATURES.md`, `LEVELS.md`, `MODDING.md`, `TESTING.md` (keep them in step when a feature changes).

## What this is

- Quake 2 levels (`maps/*.bsp`, IBSP v38), wall textures (`textures/*.wal`), models (`models/**/tris.md2`), pics/skins (`*.pcx`), skies (`env/*`) and sounds are parsed from PAK archives at runtime.
- Bundled with the Quake 2 shareware demo (`data/paks/quake2_demo.pak`, maps `demo1`..`demo3`); a full game is loaded from `baseq2/` or `-basedir` (`auto` / `gog` / `steam`, or nothing next to the game outside autotests: `QuakeInstalls.FindQuake2Installs` finds GOG / Steam / common installs, the remaster first; `--no-detect`; `castle-quake2-tests --retail auto`), a mod with `-game <folder>` / `+set game <folder>` (also in `rerelease/`, Quake II Remastered's layout). `AddGameDir` (`GameInitialize`) loads a game folder's `pak0..9.pak`, then its `.pkz` (`Pak.AddZip`, `TCastleZip`), then its loose files (`Pak.AddDirectory`); zip entries and loose files are read on first use (`TQuakePak.StreamOf`). Textures: `textures/<name>.png` / `.tga` replace the `.wal` image (WAL size kept) or stand alone (`LoadTextureReplacement`). Maps: IBSP or QBSP (`QBSP_IDENT`, `TQuakeBsp.Extended`; in memory the records are wide `TBSPNode` etc., on disk `TIBSP*` / `TQBSP*`; the level compiler writes IBSP through `NodeToIBSP` etc.). Auto doors keep the trigger field of their closed position (`TQuakeMover.TriggerField`, Quake 2 `Think_SpawnDoorTrigger`). `ChooseSpawnPoint` uses Yamagi's table of default starts for maps loaded directly (`DirectStarts`). Monsters with an `item` key drop it (`DropMonsterItem`, saved as `drops`). Monsters without a definition get a generic one when their model is loaded (`GenericMonsterDef`: `GenericMonsterFacts` lists Call of the Void's classes, model / health / movement from the mod's `SP_monster_*`, a coarse attack; else `models/monsters/<name>/tris.md2`). Keys: `ItemDefs` has the remaster's and Call of the Void's keys (`KEY_EXPLOSIVE_CHARGES` .. `KEY_Q1_RUNIC_SILVER`, bits 9..24 of `Stats.Keys`; models / names from the mod's item list, no icons yet). The mod's source (GPLv2) is not copied: write behaviour from Quake 1's, keep only facts.
- Served to CGE through memory URL protocols (`quakepak:`, `quaketex:`).
- Units: `QuakeBsp` (parser, `LightPoint`), `QuakeGeometry` (X3D batches, lightmap atlas, movers), `QuakeMd2`, `QuakePalette` (PCX/WAL), `QuakeEntities` (item/weapon/monster tables, AI), `QuakeWorld` (game rules, targets/triggers, weapons; methods in `quakeworld_*.inc` by subsystem: spawn, items, targets, movers, props, weapons, projectiles, monsters, player, save), `QuakeWeaponFrames` (the gun's Quake 2 frame state machine), `QuakeMonsterAttacks` (monster attack sequences on Quake 2's frames), `QuakeMonsterMoves` (walk / run loops with Quake 2's per-frame distances), `QuakeTrace` (box traces against BSP brushes, `CM_BoxTrace`), `QuakeTouch` (on-screen touch controls), `QuakeRecord` (the `record` command's demo-script writer), `QuakeTurret` (turret angles, muzzle, driver seat), `QuakeInstalls` (finding installed Quake II data), `QuakeTick` (the fixed game tick), `QuakeNet` / `QuakeServer` / `QuakeClient` (client / server messages over a loopback channel: usercmds, snapshots, prediction), `QuakePMove` (Quake 2's pmove for one player: the server's and the client's copy), `QuakeClientScene` (the client's models drawn from the snapshots), `QuakeInsane` (misc_insane frames, sounds: `TQuakeMonster.GoodGuy`, never alerted, not a kill, not revived), `QuakeLevel` (grid levels, JSON), `QuakeBspBuilder` (compiles a level into an IBSP v38 map), `QuakeLevelGen` (random levels, `MissingMapHook`), `QuakeLevelEditor` (the 2D level editor), `QuakeHud`, `QuakeLight` (coordinates, model tint), `QuakeSound`, `QuakeParticles`, `QuakeConsole`, `QuakeMenu`, `Game*` views.

## Build and Run (Windows)

CGE 7.0-alpha.3 snapshot with bundled FPC 3.2.2 is installed at `C:\castle-engine`:

```powershell
$env:PATH = "C:\castle-engine\bin;C:\castle-engine\tools\contrib\fpc\bin;" + $env:PATH
castle-engine compile --mode=release      # or --mode=debug
.\castle-quake2.exe
```

The log goes to `%LOCALAPPDATA%\castle-quake2\castle-quake2.log`. Audio needs `OpenAL32.dll` and `wrap_oal.dll` next to the exe.

Linux (as in CI, or a cloud container): FPC 3.2.2 (`apt install fpc libgtk-3-dev`), CGE cloned from GitHub with its build tool compiled by `tools/build-tool/castle-engine_compile.sh`, `CASTLE_ENGINE_PATH` set; autotests run under `xvfb-run -a -s "-screen 0 1600x900x24"` with Mesa.

## Automated Headless Testing

```powershell
.\castle-quake2.exe --autotest demo1 test_output\shot --demo "W:1.5,S,K,C:9,N:3,W:0.5,X,W:0.2,S,Q"
```

Demo script actions: `W:sec` wait, `S` screenshot (logs FPS + camera), `X` fire, `H` hold-fire toggle, `U` use, `C:slot` weapon (1 blaster .. 10 BFG, 11 hand grenades, 12 ion ripper, 13 phalanx, 14 traps), `K` give all, `Y` god, `A:deg` absolute yaw, `T:deg` turn, `P:deg` pitch, `M:units` move, `N:i`/`I:i`/`D:i`/`R:i` stand near monster/item/mover/prop i, `F` help computer, `G:x y z` goto (Quake coords), `E:targetname` fire targets, `O:command` console command, `V` log mover states (and `Gun: weapon state frame, ammo`, `Monster shots: N, player health ... player stuck N`, `Monsters: N alerted of M alive, K in solid`: overlapping by more than 1/16, exact contact with a wall or mover isn't stuck; each one is named with what it overlaps and the nudge that frees it), `L:map` load map, `B:key` press and release a key (CGE key name, case-insensitive, e.g. `B:escape` to drive the menu), `GP:lx ly rx ry lt rt` virtual gamepad sticks / triggers (`GP:` off), `GB:button` gamepad button (`south`, `east`, `menu`, `rb`...), `GH:button` hold / release a gamepad button, `MV:i x y z` place monster i at Quake coordinates (then always in the `V` log, with its health), `TD:x y finger` / `TM:x y finger` / `TU:finger` touch down / move / up (window fractions; run with `--touch` to show the touch controls), `O:randmap seed` / `O:editor ...` (random levels, the level editor), `IN:time yaw pitch forward side buttons [x y z]` recorded view / held inputs on the script clock (`SY:0`: don't correct the drift to the recorded position), `Q` quit. `--demo @file` reads the script from a file (commas or one command per line). Autotests use default options (`Settings.Persistent := False`, user config not loaded).

`spawn <classname> [key "value"]...` (console, also `O:spawn ...` in scripts) adds a map entity 96 units ahead of the player (or at `origin`) and spawns it like the map's own (`TQuakeWorld.SpawnEntity`); brush classes without a `*N` model take a box from `mins` / `maxs` fields (`EntityBox`, an extension for tests). Use it to test entities the demo maps lack; CI's `ents` script does.

Retail data: `tests/retail-playthrough.ps1` plays every map of an installed game (one process per map, `--log-file <file>` for each, a table of kills / monsters in solid / player stuck / warnings) and `tests/yamagi-compare.ps1 -Yamagi <dir>` takes the same start-view and help-computer shots in Yamagi Quake II (Windows release, `-datadir`) to compare the kill / secret / goal totals; both run the game minimized with `--no-sound` (no audio device) and `--offscreen-shots` (`TViewPlay.SaveScreenOffscreen`: shots drawn into a `TGLRenderToTexture`, since a minimized window reads back black). `V` logs `Kills: k / n, secrets s / n, goals g / n`.

Benchmark: `castle-quake2 --benchmark <map> <prefix>` runs `BenchmarkScript` (unit `QuakeBenchmark`) and logs `Benchmark: N frames ..., frame ms p50 / p95 / p99 / max / mean, logic ms, shapes, traces N (ms)` (`QuakeTrace.TraceCount` / `TraceSeconds`, counted in `TQuakeWorld.WorldTrace`; `--region-size <units>` sets `WorldRegionSize`, the culling regions) (demo actions `BS` / `BE` time any script part; `TViewPlay.Update` adds each frame's wall time, the time from `UpdateMovementInput` to `UpdateLoopSounds` and `MainViewport.Statistics.ShapesRendered`). CI's step *Benchmark the demo maps* writes the table to the run summary; Mesa numbers only compare CI runs. Scripted runs that ask to quit start `QuakeExitWatchdog` (process ended 20 s later if shutdown hangs; CI warns when a log has `ExitWatchdog`).

Web address settings: `QuakeWebParams.QueryToParameters` turns `?map=&skill=&touch=1&fps=1&gamma=&demo=` into command-line arguments (`+map`, `+set skill`, `--touch`, `--fps`, `-gamma`, `--autotest <map> web --demo`), added to `Parameters` on WASI (`AddWebAddressParameters`, `JSWindow.location.search`) before the one parser in `ApplicationInitialize`; `+set skill N` and `--fps` (`ShowFpsAtStart`) work on the desktop too. Web drawing resolution: `web/page.html` (manifest `<web html_contents>`, inserted after the canvas) wraps the canvas's `width` / `height` setters: the template's ResizeObserver asks for screen pixels, the page draws at most at a pixel ratio of 1.5 (measured against the canvas's CSS size: headless Chromium reports CSS pixels) and 1920 × 1080 in all, times `?scale=`; `?fullres=1` turns the caps off; it logs `Castle Quake 2: drawing at WxH`. On WASI `Parameters` can be empty, so `AddWebAddressParameters` adds the program name first (the parser starts at 1). Browser build: `node tests/web/smoke.js <dist folder or URL> [png] [timeout s] [?query]` (Playwright, Chromium with SwiftShader) serves the folder, waits for `WebAssembly library finished initialization`, clicks a canvas corner (a click on a menu row selects it) and presses Enter twice (Single Player, skill), waits for `Loaded map "maps/`, measures `requestAnimationFrame`s for 5 s, fails on GLSL errors / exceptions / page errors, writes `<png>-console.log`. The `web` workflow runs it before deploying (step summary) and retries the Pages deploy once.

Map compatibility report: `castle-quake2 --map-report report.md` (under xvfb on Linux) loads every map and lists unsupported / partial entity classes (`QuakeMapReport.EntitySupport`; add new classnames there when you implement them). `docs/map-report-demo.md` is the demo's; CI fails if the demo maps get an unsupported class.

## Unit tests

`tests/` is a console CGE project (search path `../code/`): `cd tests; castle-engine compile; ./castle-quake2-tests` — 526 checks of the parsers against the demo PAK (counts, contents, ladders, LightPoint, PVS, PHS, areas, box leafs, MD2 animations, SP2, monster types and named sounds designs, settings save / load (gamepad bindings too) and skill rules, sound attenuation and loop mixer, map report classes, player trail, gamepad mapping, gun frame timing (the Reckoning's weapons and DualFire too), monster masses, monster attack tables and timing, walk / run tables, box traces, monster jumps, touch stick, recorder, currents, gibs, particle motion, clock text, model light styles, turret math, net messages / snapshot deltas / client parsing / prediction, level JSON / BSP compiler / grid PVS / keys, slime, teleporters, ladders, lava, ramps, glass, diagonal walls, round rooms, monsters clear of walls, discovered themes / generator / sound limiter / `TQuakeMap.LevelUrl`). Run from `tests/` (it loads `../data/paks/quake2_demo.pak`). CI runs it before the autotests.

Screenshot comparison: `./castle-quake2-tests --compare reference/<map>.png <shot>.png <diff>.png [limit]` averages both images into 64x36 blocks and fails when the mean channel difference is above 3 (identical runs: < 1; a 10° turn: ~6). CI compares an `O:notarget,W:2,S,Q` shot (no combat, player settled) of each demo map with `tests/reference/*.png`. After an intended visual change, delete the affected reference and commit the one CI creates (artifact `autotest-screenshots`, `compare/reference/`), (references are made by CI's Mesa renderer; Windows shots differ by up to ~4, so don't regenerate them locally).

## CGE editor integration

- Views use designs: `data/gameviewplay.castle-user-interface`, `data/gameviewmenu.castle-user-interface` (`DesignUrl` + published fields). Change viewport / camera / navigation settings in the design, not in code.
- `editor_units` (`QuakeMap, QuakePlayer, QuakeHud, QuakeConsole, QuakeMenu, QuakeMonsterTypes, QuakeSound, QuakeLevelEditor, QuakeMapEditors`): these units call `RegisterSerializableComponent`. Children created in a component constructor must call `SetTransient`. They and everything they use are compiled into the LCL editor, so they must not use `CastleWindow` (CI job `build-editor` runs `castle-engine editor-rebuild-if-needed`; locally `apt install lazarus-ide-gtk2 lcl-gtk2 lcl-units lazarus-src`). `QuakeMapEditors` holds the design-time property editors (`MapName` dropdown from `TQuakeMap.AvailableMaps`, `PakUrl` / `LevelUrl` dialogs, *Reload Map* verb), all inside `{$ifdef CASTLE_DESIGN_MODE}`. To drive the editor headless: `xvfb-run` with `openbox` running and `xdotool` (hierarchy rows select on a double-click).
- `TQuakeMap`'s generated children (world, movers, previews) are `SetTransient`, so saving a design writes only its properties; previewed entities are `TQuakeEntityTransform`s (`TCastleToolTransform`: the editor lists and selects them although transient) with read-only `EntityClass` / `TargetName` / `Target` / `SpawnFlags` / `Fields`. Mark any new child the map builds transient.
- `TQuakeMap` also fills its published `Background` (the viewport's `TCastleBackground`) with the map's skybox in `ApplySky`, in the editor too, and `PreviewEntities` / `PreviewMarkers` show items, monsters, player starts, paths, speakers and trigger volumes in the editor (`markers` console command in game).
- `TQuakeMap` (in the play design, named `QuakeMap`) owns the BSP + geometry; `TQuakeWorld` gets it in the constructor, reuses the design-loaded map once, and calls `LoadMap` for restarts / level changes. Keep `TQuakeMap` at identity transform: gameplay code uses its local space as world space.
- Monsters, pickups and movers are `TCastleBehavior`s owned by Pascal lists (not by the transform); their destructors free the transform after `BeforeDestruction` detached them. Give runtime transforms readable `Name`s.
- World faces are culled by the PVS and areaportals in 1024-unit, per-area regions (`TQuakeGeometry.UpdateVisibility`, `Shape.Visible`); movers, monsters, items, props and lasers get `Transform.Visible := False` outside it (`TQuakeWorld.CullEntities`, by the leafs their boxes touch; they still collide). `novis` in the console draws everything. To check culling, compare shots of the same demo script with and without `O:novis` (they should match within ~1.5).
- Monster tunables live in `data/monsters.castle-transform` (`TQuakeMonsterType`, applied over `DefaultMonsterDefs` by `LoadMonsterTypes` at startup) and sound overrides in `data/sounds.castle-component` (`TQuakeNamedSound`, matched by `QuakePath`). When adding a monster or a literal sound path in code, add it to `DefaultMonsterDefs` / `DesignSoundPaths` (tests) and to the design; `castle-quake2-tests --generate-designs ../data` regenerates both files from code (overwriting editor changes).
- Player weapons run on Quake 2's gun frames (`TQuakeWorld.Gun`, `TQuakeGun`): fire, refire and switching happen on frame events, never on timers. `SelectWeapon` only queues the switch (`FStats.CurrentWeapon` changes on `geChangeWeapon`, after the put-away frames), so demo scripts need a wait after `C:slot` (about 1 s) before shots of the new weapon.
- Player collision in game is Quake 2's: `TQuakeWorld.PlayerTrace` (BSP brushes via `TQuakeCollision`, movers in model space, live monster boxes; Quake coordinates) drives `TQuakePMove.Move` (unit `QuakePMove`, `PM_StepSlideMove` etc.) on the server's copy of the player (`TQuakeServer.PM`, the world's `Player`; the view predicts with `PlayerMovement.PM`). Render meshes no longer decide where the player can go, so autotest placements (`G`, `N`, `I`, `D`, `R`) call `PlayerMovement.SnapToFreeSpace` (`N`/`I`/`D`/`R` probe render meshes first, then Quake traces: `GoNearByTraces`, for culled areas); `player stuck` in the `V` log (the server's pmove) should stay 0 in normal scripts (CI's `gekk` goto spot is in solid, before this work too). Movers carry / push the player, monsters, corpses and items in `PushPlayerByMovers` (from `OnBeforeMove`, called by the server before each command's move; Quake 2 `SV_Push`: pushed position if free, else the old one, else `TQuakeMover.Blocked`; corpses caught are gibbed, items never block; `func_rotating` only pushes the player).
- Monster attacks: `MonsterAttackSeqs` (unit `QuakeMonsterAttacks`) holds each demo monster's Quake 2 attack sequences (first frame name, length, fire frames, damage, bursts, loops); when adding a monster, add its table there (the tests check frame names against the model) or it uses the generic attack. Damage per shot comes from the table, not `TQuakeMonsterDef.Damage`. Refire loops have a `LoopCondition` (`lcSeen` with `LoopChance`, `lcRefire` = Quake 2's soldier refire: melee range or nightmare 50 %, else `SkipFrame`; `lcPause` = the dodge pause, `lcMelee` = in melee range with `LoopChance`: the flyer's slashes), `MinDist` keeps a sequence for longer ranges (tank rockets beyond 250), `auDodge` sequences (soldier attack3) only start from `TQuakeMonster.Dodge`, and `DuckFrom`..`DuckTo` lower the shot box. Starts are logged (`<monster> attacks: <first frame>`).
- Full game monsters (gladiator .. Makron): their tables are in the same units; extra `TMonsterAttackSeq` fields: `Volley` (shots per fire frame), `Kick` (fire_hit push, negative pulls), `Radius` (akBfg effect), `AimFrame` (shoot at the target position saved on that frame: `AimSaved` / `SavedAim`, `TQuakeWorld.MonsterRail`), `Sweep` (`SweepYaw`), `Weight` (weighted `ChooseAttackSeq`); kinds `akBfg`, `akLeap` (`TQuakeMonster.Leap`, `LeapDamage` on touch in `UpdateBossesAndLeaps`). Jorg: `Model.Follower` draws `boss3/jorg` on the rider's frames; its death queues `FMakronTosses` (Makron spawned 5.6 s later, jumping at the player, with Jorg's target). The Makron's own frames on the rider model are chosen by `TQuakeMonster.AnimNames`. Check the tables with `castle-quake2-tests --retail <pak>` (needs a retail PAK, e.g. `-basedir "E:/GOG/Quake II Enhanced"` for the game).
- Call of the Void's Quake 1 monsters: unit `QuakeQ1Monsters` (`Q1Archetype(class)` for the variants whose model has Quake 1's frame count, `$frame` orders, `Q1FrameIndex`, `Q1AnimRange`), checked first by `MonsterAttackSeqs` / `MonsterMoveSeq` (some mod classes start with `monster_soldier`). Their tables address frames by index: `FirstFrame` `'#<index>'` (`TQuakeMonster.FrameOf`), animations `'#first:count'` (`TQuakeMd2.FindAnim`, `TQuakeMonster.Q1AnimNames`). `AdaptVariantAttacks` gives a generic-def variant its own weapon. Attack seq fields `MaxLoops`, `Speed`, `YawStep` / `YawCenter`, `LeapForward` / `LeapUp`. Facts come from id's QuakeC (`id-Software/quake-rerelease-qc`, GPLv2): no code copied.
- Monster steps are refused when the new spot overlaps solid (`TQuakeMonster.ClearToMoveTo`, a position test 1/16 smaller: a swept trace stops at the floor at fraction 0 and can miss a ledge); movers push flyers too. Monster movement: `MonsterMoveSeq(class, Run)` (unit `QuakeMonsterMoves`) holds each demo monster's walk / run loop (first frame, `ai_walk` / `ai_run` distance per frame); `TQuakeMonster.AdvanceMove` plays it while chasing / patrolling and `TryMove` moves at the frame's distance × 10 a second (constant `Def^.Speed` only without a table or model). When adding a monster, add its tables there too (the tests check the frame names).
- Touch: `TQuakeTouchControls` (unit `QuakeTouch`) is created by `TViewPlay.Start` when `TouchControlsWanted` (`ApplicationProperties.TouchDevice` or `--touch`) and inserted in front of the viewport, behind the menu and console. `UpdateMovementInput` reads `Stick`, `TakeLook` (pixels, times `LookDegreesPerPixel` and the mouse sensitivity) and `Held(tb...)`; with touch controls the left mouse button no longer fires (every touch is a left button) and mouse look is off. `TQuakeMenu` selects / activates rows by tap (`ItemAt` mirrors `Render`'s layout). Android: CI job `build-android` runs `castle-engine package --target=android`.
- Recording: the `record <name>` / `stop` console commands (`TViewPlay.StartRecording` / `StopRecording`, unit `QuakeRecord`, `TQuakeRecorder`) sample the aim, `PlayerMovement.Input*` and firing at the end of `TViewPlay.Update` into `IN:` lines, and add instant actions through `RecordCommand` (`DoSelectWeapon`, `DoUse`, `DoToggleHelp`, console commands). New player actions should go through such a `Do...` method so recordings keep them. Scripts are saved to `castle-config:/recordings/<name>.txt`; CI records a scripted run and checks its replay ends within 8 units. A sample's position is after that frame's move, so the replay corrects drift after the move too (`ApplyDemoSync`).
- Gamepads: `QuakeGamepad` (pure mapping functions + `ReadGamepads`, which sums CGE's `Controllers` and the demo scripts' `VirtualGamepad`). Sticks / triggers are polled in `TViewPlay.UpdateMovementInput` (look goes through `PlayerMovement.InputYaw` / `InputPitch`, applied to the view without effects before pmove); buttons arrive as `itGameController` press events (`TQuakeMenu.Press` turns them into menu keys with `GamepadMenuEvent`, so pass it raw events: the *Gamepad Buttons* page binds buttons). Button actions are bound in `Settings.PadButtons[pa...]` (`TPadAction`, `BindPadButton` swaps, `PadButtonBindable`: not Menu, Guide, D-pad up / down); read them through `Settings.PadActionOf`, never hard-code face buttons. `padbind [<action> <button> | reset]` in the console. Controllers are not initialized in autotests.
- UI size: CGE scales the UI to the 1600 × 900 reference (`data/CastleSettings.xml`); custom `Render` code multiplies its sizes by `UIScale * InterfaceScale` (`QuakeSettings`: *Options → Interface Size*, Auto is `TouchInterfaceScale` on touch screens) and draws text with `UIFont.PushProperties`, `UIFont.Size := UIFont.EffectiveSize * scale`, `PopProperties`. At 1600 × 900 on desktop both are 1, so screenshots don't change. Try phone layouts with `--geometry 2400x1080 --touch` (xvfb screen at least that big).
- Players (E.2, step 1): one player's state is a `TQuakePlayer` (`Stats`, `Pos` / `Dir`, `PM`, `Gun`, fire latches, `Dead` / `Gibbed` / killer, pain / air / liquid / breath timers, `DamageSource`, `Gravity`); the world keeps them in `Players` and acts on `FCur` (`CurrentPlayer`, player 1 in single player). New per-player state goes into `TQuakePlayer`, read as `FCur.X`, never into a new world field.
- Client / server (E.1): after its ticks the play view predicts the player (`TViewPlay.MoveAndSend` → `PlayerMovement.MoveNow` → `OnPredict` = `TQuakeClient.Predict`: the last snapshot's pmove state, the commands it hasn't run, this frame's) and sends a `TNetUserCmd` (angles, moves, buttons, msec, sequence) and string commands (`FClient.AddCommand`) over `TNetLoopback`; `TQuakeServer.ReadPackets` runs them at once: pushes by movers, pmove on `TQuakeServer.PM`, fire; string commands `use`, `weapon N`, the console's `god` / `give` / `powerarmor` / `notarget` / `noclip` / `kill` / `spawn` / `hurt`, the demo actions `E` (`fire`), `MV` (`mv`), `K`, `Y` (`ExecuteString`; replies as `svc_print` / `svc_centerprint`). Never change the game from the view (`FWorld.FireWeapon`, cheats, spawns...): add a string command, sent from a `Do...` method or the console; map loads, saves and the editor stay in the view. A camera moved by code is noticed before the next prediction (`PlacePlayer` keeping the velocity); `PlaceCamera` / `LoadGame` place with a reset. `RunTick` runs the world tick with the player's last known view (`NewMap` after a map load) and `SendFrame` sends a delta-coded snapshot (player state with pmove state and `CommandAck`, entities in the PVS) each tick. The client draws the md2 models from the snapshots (`TQuakeClientScene.Update` after `MoveAndSend`: pose between the last two snapshots by `FTickClock.Alpha`, the server's frame blend `OldFrame` / `Frame` / `Lerp`, skin, scale, shells, `NetRfIrVisible`, own light tint) while `TQuakeServer.HideModels` hides the server's md2 scenes (`Scene.Visible`; they still collide); a new visual property of a model must go into `TNetEntityState` (server `BuildFrame`, client scene) or it vanishes from the screen. `clientdraw [0|1]` / `--server-draw` draw the server's models; CI's compare step checks both match. `CheckSnapshot` compares the client's copy with the server's; `V` logs `Net: ... M of K checked differ, prediction checked N times, E off by more than 1/8` (CI's `net` script wants 0 differing) and `Player:` (server / client origins). Trace hits on the player are `T.Ent is TQuakePMove` (or `= FPlayer`).
- Fixed tick: `TViewPlay.RunTicks` runs `TQuakeWorld.Update(TickSeconds)` (via `TQuakeServer.RunTick`) 40 times a second (`TQuakeTickClock.AddFrame`, at most `MaxTicksPerFrame`); per-frame work (movers, `TQuakeGeometry.Update`, particles) is in `TQuakeWorld.UpdateFrame`, and the player moves every frame. `TViewPlay.InternalRenderLoop` moves the transforms of `CollectMovingTransforms` (monsters, items, props, projectiles) to `TickDrawnPose` for drawing and restores them right after (`Apply` / `Restore`): gameplay code always sees the simulated poses. New code that moves an entity's transform in the simulation belongs in `Update`; if the entity has a new kind of list, add it to `CollectMovingTransforms`. A tick that sets `RestartPending` / `TeleportPending` / `LevelExited` ends the frame's ticks.
- Render scale: `Settings.RenderScale` (percent, *Options → Render Scale*, `renderscale`, `--render-scale` = `TViewPlay.RenderScaleOverride`). Below 100, `TViewPlay.InternalRenderLoop` draws the design root's children itself: `RenderScaled3D` shrinks `MainViewport` and `WeaponViewport` with a temporary `Border` (right / top) to W × H, renders both into `FScaledView` (`TDrawableImage.RenderToImageBegin`, color + depth) and draws it over their rectangle; the HUD, console and menu draw normally. Keep both viewports direct children of the design root, at its origin (else it falls back to full resolution). Logged as `Render scale N%: 3D view drawn at WxH`.

## Conventions & Rules

- 2-space indent, `begin`/`end` on their own lines, PascalCase, no `with`.
- Coordinates: `CGE.X = Quake.X`, `CGE.Y = Quake.Z`, `CGE.Z = -Quake.Y` (`QuakeToCge`). Quake yaw maps to a rotation around +Y by the same angle (`YawToCgeDir`).
- BSP polygons and MD2 triangles are clockwise from the front: `Ccw := False`.
- CGE images are bottom-to-top; PCX/WAL decoders flip rows, so UV `v = 1 - t/height`.
- `TCastleBackground.TexturePositiveZ` is the X3D "front" drawn at **-Z** (and `TextureNegativeZ` at +Z).
- Sounds: the mixer (`Sounds.UpdateMixer`, every frame) compresses the master volume when the summed gain of the playing sounds and loops passes 3, and spatial sounds get Quake 2's stereo loudness (`QuakePanLoudness`, needs `Sounds.ListenerRight`). Use `Sounds.Play(path, volume, channel)` for the player (2D), `PlayAt(path, transform, volume, attenuation, channel)` / `PlayAtPoint(path, position, ...)` for the world, with Quake 2's `CHAN_*` as `chWeapon` / `chVoice` / `chItem` / `chBody` (same owner + channel replaces the previous sound). Never attach looping `TCastleSoundSource`s to entities: report looping sounds each frame through `TQuakeWorld.UpdateLoopSounds` (loop mixer). To listen headless, run with `ALSOFT_CONF` pointing to an OpenAL Soft config with `drivers = wave` and `sample-type = int16`.
- Player items: `FStats.BreatherTime` / `EnviroTime` (air in `UpdateLiquids`, lava / slime), `SilencerShots` (`WeaponNoise` and `SilencedVolume` instead of `PlayerNoise` / volume 1 for weapon fire), `PowerScreens` / `PowerShields` / `PowerArmorOn` (`AbsorbPlayerPowerArmor` in `DamagePlayer`, before armor; `NoArmor` skips both, for drowning). Used on pickup (`GiveItem`, `POWERUP_OTHER`); `give <item name>` (`CheatGiveItem`) and `powerarmor` (`TogglePowerArmor`) in the console.
- BFG: a `pkBfg` projectile fires `BfgLasers` every 0.1 s in flight (`LaserTimer`); on impact it stays as `Exploding` (hidden, `Life` 0.1, saved) and `BfgEffect` runs when that runs out (`SplashDamage` 500 × quad, `SplashRadius` 1000; `Particles.SpawnBfgHit` = `s_bfg2`).
- Underwater warp: `TViewPlay.CreateWaterWarp` adds a `TScreenEffectNode` (`D_WarpScreen`'s sine shifts, uniform `time`) to `MainViewport`, enabled while `Hud.UnderwaterType <> 0` (`UpdateWaterWarp`); the node belongs to the viewport's screen-effects scene.
- View effects (bob, landing dip, damage kicks, weapon bob / lag) are applied to the camera by `TQuakePlayerMovement` after pmove and removed before the next move. Aim, use and save with `PlayerMovement.AimPosition` / `AimDirection`, not the camera; call `PlayerMovement.ClearViewEffects` before moving or turning the camera from code.
- Particles are data (`TQuakeParticle`: spawn position, velocity, gravity, life, sizes, `SpawnTime`) drawn by one batched scene; add them with `AddParticle`. The mesh holds the spawn data and is rebuilt (`RebuildBatch`) only when particles are added or most have expired; a vertex shader (`q2p_*` attributes and uniforms, `CreateBatchScene`) moves, sizes, fades and turns them to the camera (`TQuakeParticle.PositionAt` is the same motion on the CPU; expired quads shrink to a point). The scene has frustum culling off. `V` logs `Particles: N (mesh uploads M)`. Set `Particles.Camera`. (If you use `TBillboardNode` elsewhere, it needs `Scene.ProcessEvents := True`.)
- Don't use `MODULATE2X`/`MODULATE4X` multi-texture modes: CGE emits an int literal (`*= 2;`) that breaks WebGL shaders. Scale the unlit emissive colour instead. Check web logs for `GLSL: Fragment shader not compiled`.
- Dynamic lights: `Lighting.AddLight(pos, radius, color, duration)` (duration 0 = this frame only, re-add every frame). World surfaces show the 4 nearest via the lightmap texture effect in `TQuakeGeometry.CreateDLightEffect`; create one effect per scene, never share X3D nodes between scenes.
- Light styles: `TQuakeLighting` owns style patterns/values (`Version` bumps on change); `TQuakeDynamicLightmap` recomposes the light-style atlas and calls `Node.FdImage.Changed`. Lightmaps of a face are `styles` consecutive RGB blocks.
- `TQuakeMd2Instance.PlayAnim('')` plays all frames (banners, effects).
- Autotests disable mouse look (results must not depend on the desktop mouse). CI runs the same scripts on Linux under xvfb + Mesa (`.github/workflows/build.yml`, job `autotest`).
- Monster boxes: `QuakeMonsterBox` is Quake's (True for the carrier and the turret, kept as they are); `MonsterBoxSize` moves the others' bottom to 24 below our origin, so models are drawn `MonsterModelOffset` = -24 - mins.z lower (`Model.Scene.Translation`, also Jorg's legs; the ceiling stalker the other way): the chick, Jorg, the Makron, the supertank and the Widows by 24, the tank by 8.
- Collisions, shots and sight go through `TQuakeWorld.WorldTrace` (also `EntityTrace` for monsters): map brushes, movers, monster boxes (`BoxMins` / `ShotBoxMaxs`), the player's box, corpses and barrels, with Quake 2 masks (`MASK_PLAYERSOLID`, `MASK_MONSTERSOLID`, `MASK_SHOT`, `MASK_OPAQUE`) and an `Ignore` entity; the hit is `T.Ent`. Don't use `WorldRayCast` / CGE collisions for gameplay any more (render meshes aren't the brushes). Model scenes still set `Collides := False`, `Pickable := False` where they don't need CGE picking.
