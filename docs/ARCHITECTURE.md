# Castle Quake 2: Architecture & Technical Design

How Quake 2 game data is parsed and played in the **Castle Game Engine (CGE)**, and which engine features each subsystem uses. The structure mirrors [castle-quake1](https://github.com/mariuz/castle-quake1); this document focuses on what is different for Quake 2.

---

## 1. Data flow

```
 quake2_demo.pak / baseq2/pak*.pak
              │
              ▼
        QuakePak (PACK reader, "quakepak:" protocol, MIME from extension)
     ┌────────┼──────────────────────────┬──────────────────────┐
     ▼        ▼                          ▼                      ▼
 QuakePalette  QuakeBsp (IBSP v38)    QuakeMd2 (IDP2 v8)     QuakeSound
 colormap.pcx  entities, planes,      unwelded meshes,       WAV via
 PCX + WAL     nodes, faces, texinfo, frame lerp, skins      TCastleSound /
 "quaketex:"   RGB lightmaps,                                TCastleSoundSource
     │         LightPoint()                 │
     │             │                        │
     └──────┬──────┴──────────┬─────────────┘
            ▼                 ▼
     QuakeGeometry       QuakeEntities (item / weapon / monster tables,
     X3D batches,        pickups, monster AI, projectiles, triggers)
     lightmap atlas,          │
     movers, sky clip         │
            └───────┬─────────┘
                    ▼
               QuakeWorld  (G_UseTargets, triggers, weapons, damage, armor,
                    │       level changes, teleporters)
                    ▼
               GameViewPlay (TCastleView)
               ├── TCastleViewport + TCastleWalkNavigation + TCastleBackground (skybox)
               ├── QuakeHud (pics/*.pcx via TDrawableImage)
               ├── QuakeParticles (one batched scene of camera-facing quads)
               └── QuakeConsole / QuakeMenu
```

## 2. Coordinates

Quake: X east, Y north, Z up. CGE: Y up.

- `CGE = (Quake.X, Quake.Z, -Quake.Y)` (`QuakeToCge`), determinant +1, so windings are preserved.
- A Quake yaw `a` (0 = east, 90 = north) is a CGE rotation of `a` around +Y; the facing vector is `(cos a, 0, -sin a)` (`YawToCgeDir`).
- Quake 2 player: origin 24 above the feet, eye 22 above the origin → eye height 46 (22 when crouched), 18-unit steps, 300 u/s run.

### Player movement

**In game the player moves with box traces, like Quake 2.** Unit `QuakeTrace` ports `cmodel.c`: `TQuakeCollision.BoxTrace(Start, Stop, Mins, Maxs, HeadNode, Mask)` is `CM_BoxTrace` (`CM_RecursiveHullCheck` down the BSP, `CM_ClipBoxToBrush` against the convex brushes of each leaf with `DIST_EPSILON` 1/32, position tests through `CM_TestBoxInBrush` when Start = Stop), in Quake coordinates; `TQuakeBsp` now keeps the brushes, brush sides and leaf brushes. `TQuakeWorld.PlayerTrace` (the player's `OnTrace`) combines the world model, every existing mover (its brush model's head node, the points taken into model space by the inverse of the mover transform plus `BaseOffset`, like `CM_TransformedBoxTrace`) and live monsters as boxes (`BoxTraceAgainstBox`; corpses don't block), keeping the nearest hit like `SV_ClipMoveToEntities`. With it `TQuakePlayerMovement.PMMove` is `Pmove`: `PM_CheckDuck` (duck on the ground, stand up when the standing box fits), `PM_CatagorizePosition` (on ground when a 0.25-unit trace down hits a plane with normal z ≥ 0.7; water level at feet, waist and eyes; hard landings block jumps for 144–200 ms), ladder detection by a 1-unit trace forward hitting `CONTENTS_LADDER`, `PM_CheckJump`, `PM_Friction` (ground / ladder and water friction, on the full velocity), `PM_WaterMove` / `PM_AirMove` (ladder climbing rules, ground and air acceleration, gravity) and `PM_StepSlideMove`: slide with up to 4 bumps clipping the velocity against every plane hit (`PM_ClipVelocity` 1.01 overbounce, creases between two planes), then again from 18 units higher pushed back down, keeping the move that got further on walkable ground. The origin is the box centre (feet − 24); the camera sits `FViewZ` above it (22 standing, −2 ducked, followed within 0.1 s) minus a step offset that smooths the view over stairs (Quake 2's `predicted_step`). A move that starts inside a solid is nudged out (`PMUnstick`, counted in `StuckCount`, logged by `V`); `SnapToFreeSpace` settles the box after autotest placements. Movers carry what stands on them and push what they move into (`TQuakeWorld.PushPlayerByMovers`, run from the player's `OnBeforeMove` right before each move): the player, monsters, corpses (low boxes) and items (Quake 2's ±15 boxes). An entity rides a mover when a 1-unit trace down from it hits the mover's previous pose; it is pushed when the mover's new pose overlaps it and the old one didn't. The frame-to-frame mover matrix is applied to its origin (rotating movers carry along the arc); pushes over 64 units in a frame are ignored (the rotated-box approximation catching something far away) and `func_rotating` pushes only the player. When the pushed position isn't free and the old one isn't either, the mover is blocked like Quake 2's `SV_Push`: `TQuakeMover.Blocked` (at most every 0.1 s) returns the damage (`dmg`: doors and plats 2, trains 100 unless TRAIN_BLOCK_STOPS, func_rotating 0) and sends doors (unless DOOR_CRUSHER or wait −1) and plats back the other way. Monsters don't walk into the player's box (`PlayerBlockBox` in `TQuakeMonster.TryMove`). `trigger_monsterjump` (`TQuakeWorld.CheckMonsterTriggers`) throws walking monsters touching it: horizontal velocity `speed` (200) along its angle always, `height` (200) up when on the ground, then `TQuakeMonster.UpdateJump` flies them under gravity 800 until they land. Without `OnTrace` (editor, tests) the older overlap-test movement below runs.

`TQuakePlayerMovement` (unit `QuakePlayer`) is a `TCastleBehavior` of the camera that ports the core of Quake 2's `pmove.c`: `PM_Friction` (stop speed 100, friction 6), `PM_Accelerate` (10 on the ground, 1 in the air), gravity 800, jump 270 (needs the key released in between), crouching. Collision uses CGE's world queries with Quake 2's player box (32 × 32 × 56, ducked 32; `BoxCollision`, default on): a horizontal move is allowed when `WorldBoxCollision` finds nothing in the box at the new place with its bottom raised by the step size (so it passes over stairs), sliding along the X / Z axes when blocked; ceilings and standing up check a thin box above the head. `WorldHeight` below the centre (and below the box corners when the centre has no ground within a step, so you stand on ledge edges) steps up stairs (≤ 18 units), refuses higher obstacles, sticks to the ground going down and lands. `BoxCollision = false` uses the older eye sphere (`WorldMoveAllowed` with wall sliding). Landing speed gives Quake 2's falling damage (`delta = v² × 0.0001`, damage `(delta − 30) / 2`). `trigger_push` sets the velocity to `movedir × speed × 10`. `TCastleWalkNavigation` keeps only mouse look (its movement inputs are cleared).

## 3. Textures and images (`QuakePalette`)

| Quake 2 asset | Format | Handling |
| --- | --- | --- |
| `pics/colormap.pcx` | 8-bit PCX | Its 256-color palette becomes the global palette. |
| `textures/*.wal` | 8-bit, mip levels, `animname`, flags | Mip 0 decoded with the global palette; size / `animname` / flags cached in `TQuakeWalInfo`. |
| Model skins, HUD pics, `env/*.pcx` | 8-bit RLE PCX with own palette | Decoded with their embedded palette; index 255 transparent for skins and pics. |
| `env/*.tga` | TGA | Loaded directly by CGE from `quakepak:` (MIME type derived from the extension). |

Decoded images are cached and served as uncompressed TGA streams through the `quaketex:` URL protocol, so CGE's texture cache, mipmapping and `TTexturePropertiesNode` filtering apply unchanged. Rows are flipped to CGE's bottom-to-top order, so UV `v = 1 - t / height`.

## 4. BSP and world geometry (`QuakeBsp`, `QuakeGeometry`)

- IBSP v38 header with 19 lumps. Planes, nodes, vertices, edges, surfedges, texinfo (76 bytes, with the texture name, flags, value and `nexttexinfo`), faces (20 bytes, 4 light styles), models (48 bytes) and the RGB lighting lump are read.
- Per face, the lightmap extents are computed like Quake 2's `CalcSurfaceExtents` (16-unit luxels), stored in `TQuakeFaceExtents`.
- Faces are batched by texture name + `SURF_WARP | SURF_TRANS33 | SURF_TRANS66 | SURF_FLOWING` into `TIndexedTriangleSetNode` shapes (`Ccw := False`).
- **Lightmaps**: each face's first-style RGB block is shelf-packed into a 2048² (world) or 512² (brush model) `TRGBImage` atlas with 1 texel padding. Batches use `TMultiTextureNode` with two `MODULATE` stages (WAL texture, lightmap) and an unlit material whose `EmissiveColor` is (2, 2, 2) for the overbright factor. (`MODULATE2X` would be the natural choice, but CGE generates `*= 2;` for it, which WebGL's GLSL ES rejects.) A 4×4 neutral (128) block serves faces without lightmaps. `-gamma` lifts dark lightmaps (default 1.2).
- **PVS culling** (Quake 2 `R_MarkLeaves`): `TQuakeBsp` keeps the visibility lump, leaf faces and leaf clusters; `PointCluster` finds the camera's cluster and `ClusterPVS` run-length decompresses its row (`CM_DecompressVis`). `TQuakeGeometry.BuildVisRegions` puts each world face into a 1024-unit grid cell (a `TQuakeVisRegion`, which also splits the texture batches) and ORs in the clusters of all leafs listing its faces. `UpdateVisibility` (called by `TViewPlay.Update` with the camera position) recomputes only when the cluster changes and sets `Shape.Visible` (rendering only: hidden shapes still collide). Regions are also split by area (the area of the first leaf listing a face) and record the areas of all leafs listing their faces: `TQuakeBsp.FloodAreas` (`CM_FloodArea`) finds the areas connected to the camera's area through open portals, and a region must hit both the PVS and those areas. A `TQuakeAreaPortal` (`func_areaportal`, portal number in `style`) is open while a door targeting it is not closed (Quake 2 `door_use_areaportals`), otherwise it toggles when used (`ToggleAreaPortal`, saved as `areaPortals`). Cluster -1 (outside the map, noclip in a wall) or `NoVis` shows everything. Entities are culled the same way, like Quake 2's `SV_BuildClientFrame`: every frame `TQuakeWorld.CullEntities` asks `TQuakeGeometry.BoxVisible` for the bounding box of each mover (`WorldBox`), monster, item, prop and laser; `TQuakeBsp.BoxLeafs` (`CM_BoxLeafnums`) lists the leafs the box touches (more than 64: drawn) and the entity is shown when one of them is in a potentially visible cluster and a connected area. Hidden transforms get `Visible := False`, so they still collide and are hit by ray casts. Gibs, debris, projectiles and particles are not culled. Autotest screenshots log the cluster and the visible / total regions.
- **Player clip**: brushes with `CONTENTS_PLAYERCLIP` (and not solid) have no faces; their polygons are rebuilt from the brush planes (a huge quad on each plane clipped by the others) into an invisible, non-pickable `PlayerClip` scene, so they block walking but not shots.
- **Ladders**: `TQuakeBsp.PointInLadder` tests points against the ladder brushes' planes. Leaf contents can't be used: ladders are detail brushes, which don't split leafs.
- **Sky**: `SURF_SKY` faces go to a separate invisible (`Visible := False`) but colliding scene, so the player can't leave the map while the skybox (`TCastleBackground`, built from `worldspawn.sky` by `TQuakeMap.ApplySky` into the map's published `Background`, so the editor shows it too) shows through.
- **Translucent / warp / flowing**: `SURF_TRANS33/66` become blended with 0.67 / 0.34 transparency; `SURF_FLOWING` gets a `TTextureTransformNode` scrolled like Quake 2 GL (`-64 * frac(t/40)`).
- **Animated textures** follow WAL `animname` chains and are switched at 2 frames/second by changing `TImageTextureNode` URLs.
- **Light styles**: a face stores up to 4 style indices and one RGB lightmap block per style. Faces whose styles are all 0 use the static atlas. Others go into a separate dynamic atlas (1024² for the world, 256² for brush models) with their own batches; `TQuakeDynamicLightmap.Compose` sums `block[i] * StyleValue(style[i])` per texel, applies the gamma and calls `FdImage.Changed` to re-upload. `TQuakeLighting` evaluates Quake 2's style strings (`'a'` = 0, `'m'` = 1, `'z'` ≈ 2) at 10 Hz, switchable lights (styles 32+) and `target_lightramp` ramps, and increments `Version` only when a value changes, so static frames cost nothing.
- **Dynamic lights** (Quake 2 `dlight_t`): `TQuakeLighting.AddLight` keeps timed lights (muzzle flashes 0.1 s, explosions 0.5 s, shrinking) and single-frame lights (rockets, blaster bolts, BFG balls, re-added every frame and dropped by `EndFrame`). Every frame `TQuakeWorld.SetSurfaceLights` sends the 4 nearest (`NearestLights`) to `TQuakeGeometry.SetSurfaceLights`. Each brush model's lightmap textures carry an `Effect` (one per model, since X3D nodes can't be shared by scenes) whose vertex part passes the object-space position (= world space) and whose `PLUG_texture_color` adds `color * (radius - distance) / 256` to the lightmap sample before it modulates the wall texture, like `R_AddDynamicLights`. `SampleLight` adds the same term to model tints.

### Movers

Brush entities (`model "*N"`, classname `func_*`) are separate `TCastleScene`s in `TCastleTransform`s (`TQuakeMover`). Entities with an origin brush store vertices relative to `origin`, so the transform starts at the entity origin.

| Classname | Behaviour |
| --- | --- |
| `func_door`, `func_door_secret`, `func_water` | Slides along `angle` (-1 up, -2 down) by size − `lip`; `wait` (−1 = toggle), `DOOR_START_OPEN`. Doors without `targetname`/`health` open when the player enters the box expanded by 60 units. |
| `func_door_rotating` | Rotates `distance` degrees around Z / X / Y axis (spawnflags). |
| `func_plat` | Built at the top, starts at the bottom, rises when stood on, waits 3 s. |
| `func_button` | Pushed by touch, `E`, or shooting (`health`); fires its targets. |
| `func_rotating` | Spins at `speed` deg/s; toggled when targeted. |
| `func_train` | Moves through the `path_corner` chain (`corner.origin − model.mins`), honours `wait` and `pathtarget`. |
| `func_wall`, `func_object` | Static; toggled visible when targeted. |
| `func_explosive` | Shootable (default 100 health when untargeted), explodes, chain-reacts through splash damage. |

## 4b. Sound

`TQuakeSounds` (unit `QuakeSound`) follows Quake 2's `snd_dma.c`:

- **Attenuation**: full volume up to `SOUND_FULLVOLUME` (80 units), then `1 - distance × dist_mult` with `dist_mult = 0.0005 × attenuation` (`0.001 × 3` for `ATTN_STATIC`). That is OpenAL's clamped linear model (`SoundEngine.DistanceModel := dmLinear`) with `ReferenceDistance = 80` and `MaxDistance = 80 + 1 / dist_mult`; `TCastleSound`s are cached per path and `dist_mult`. `ATTN_NONE` (0) plays as a 2D sound.
- **Channels** (`TQuakeSoundChannel`: `chAuto`, `chWeapon`, `chVoice`, `chItem`, `chBody`, Quake 2's `CHAN_*`): a sound on the same owner and channel stops the previous one (`chAuto` never does). The player's 2D sounds use owner nil: weapon fire on `chWeapon` (rapid fire doesn't pile up), pain / death / no-ammo / falls on `chVoice`, pickups and quad on `chItem`, water on `chBody`. Monsters: sight / pain / death / idle / search on `chVoice`, attacks on `chWeapon`, gibs on `chBody`. Movers: start / end sounds on `chVoice`.
- **Point sounds**: `PlayAt(path, transform)` and `PlayAtPoint(path, position)` play from a throwaway emitter with `TCastlePlayingSoundSource.Follow := False`, so the sound keeps playing where it started after the transform is hidden or freed (gibs, exploding projectiles, level changes). Explosions (`rocklx1a`, `bfg__x1b`), blaster impacts and `target_splash` sparks are heard from where they happen; movers play from `Center` (their transform origin can be far from the brush).
- **Loops** (Quake 2 `S_AddLoopSounds`): looping `target_speaker`s and moving doors / plats don't own sources. Every frame `TQuakeWorld.UpdateLoopSounds` passes the active emitters in the PVS / connected areas (`TQuakeGeometry.BoxVisible`) to `Sounds.BeginLoops` / `AddLoop` / `EndLoops`; each distinct sound has one voice (`TQuakeLoopVoice`, a transform with a looping `TCastleSoundSource` in `Sounds.WorldParent`) placed at its loudest emitter, with `SOUND_LOOPATTENUATE` (0.003: silent beyond ~413 units). demo1 has 84 speakers but plays 1–3 loops at a time.
- **Sources**: `SoundEngine.MaxAllocatedSources := 32` (Quake 2 `MAX_CHANNELS`). Before the loop mixer, every looping speaker held a source, so the default 16 were exhausted and one-shot sounds (explosions, pain) were dropped.

Audio can be checked headless with OpenAL Soft's wave backend (`ALSOFT_CONF` with `drivers = wave`, `sample-type = int16`, `[wave] file = ...`): it writes the final mix to a WAV file.

## 5. Models (`QuakeMd2`)

- MD2 indexes positions and texture coordinates separately; triangle corners are "unwelded" into unique (xyz, st) pairs so X3D can use one index list.
- Every frame is decompressed into a `TVector3List` in CGE coordinates. Animations are grouped by frame name (`run3` → `run`, `attak105` → `attak1`).
- `TQuakeMd2Instance` owns a scene, plays an animation by name with fallbacks (`'attak,attack,fire,...'`), and linearly interpolates between frames by rewriting the `TCoordinateNode` only when the frame / blend changes. `SetShell(Color)` adds (lazily, in a `Switch`) a second shape: the same triangles with vertices moved 4 units along smoothed normals (`TQuakeMd2.OffsetAlongNormals`, summed per original MD2 vertex so UV seams don't crack), unlit, alpha 0.3, back faces culled. The view weapon uses it for quad (blue) / invulnerability (red); monsters for power armor (`AbsorbPowerArmor`, Quake 2 `CheckPowerArmor`: screen absorbs a third of the damage at 1 cell per point, shield two thirds at 2 points per cell; green for 0.2 s).
- Lighting: models use an unlit material whose `EmissiveColor` is the lightmap color sampled under the model with `TQuakeBsp.LightPoint` (Quake 2's `RecursiveLightPoint` through the BSP nodes), ×2 overbright, plus the dynamic lights.

## 6. Game logic (`QuakeWorld`, `QuakeEntities`)

- **Tables** (`ItemDefs`, `WeaponDefs`, `MonsterDefs`) map Quake 2 classnames to models, icons, sounds and numbers, so adding an item or monster is a table row. Monsters come from `DefaultMonsterDefs`, then `LoadMonsterTypes` (unit `QuakeMonsterTypes`) applies `data/monsters.castle-transform` over `MonsterDefs` by `MonsterClass` (replacing or adding entries) before any monster exists, since `FindMonsterDef` returns pointers into the array.
- **Targets**: `UseTargets(targetname)` implements `G_UseTargets` for movers, `trigger_relay`, `trigger_counter`, `trigger_key`, `target_changelevel` (`map$spawn`), `target_secret`, `target_goal`, `target_help`, `target_speaker`, `target_explosion`, monsters (wake up) and `TRIGGERED` triggers (enable); `delay` is queued.
- **Triggers** use the brush model bounds; `misc_teleporter` uses a box around its origin and moves the camera to `misc_teleporter_dest`.
- **Weapons**: hitscan pellets with Quake 2 spreads (`SpreadDir`, units at 8192) are point traces of `TQuakeWorld.WorldTrace` with `MASK_SHOT` (map brushes, movers, live monster boxes with `ShotBoxMaxs` 32 lower while ducking, corpses as low boxes, barrels and dead soldiers); `T.Ent` says what was hit (monster, mover, prop, player). The railgun pierces by tracing on from the hit, ignoring that monster. Projectiles trace each step (ignoring their shooter), so monster bolts hit the player's box; grenades bounce off the hit plane (`ClipVelocity` overbounce 1.5, stop on floors when slow) and explode on monsters / the player or their fuse. `CheckDodge`, `target_laser` (which also hurts monsters now) and the player trail's visibility use the same traces.
- **Monster movement** uses the traces too (`EntityTrace`, set by the world): `MonsterBoxSize` gives each class Quake 2's box (moved so the bottom is 24 below the origin like every monster here); `TQuakeMonster.StepMove` is `SV_movestep` (from a step above the wished spot push down two steps; refuse all-solid starts and moves with nothing below) with `CheckBottom` (`M_CheckBottom`: the middle and the four corners of the box bottom need ground within 18 units), so monsters climb stairs, never walk off ledges, collide with each other and the player and with monster-clip but not player-clip brushes. Flyers need the whole move free. Gravity, `trigger_monsterjump` flight and the first-frame drop to the floor (`DropToFloor`, `M_droptofloor`) trace as well; sight (`SightClear`) is a point trace against `MASK_OPAQUE` (doors block it, windows don't). The `V` log counts monsters in solid. - **Gun frames** (unit `QuakeWeaponFrames`, Quake 2 `p_weapon.c`): `TQuakeGun` is `Weapon_Generic` / `Weapon_Grenade` as plain code, stepped at 10 Hz over the view model's frames. `GunFrameDef(Slot)` holds the Quake 2 frame ranges (activate / fire / idle / put away, e.g. blaster 4, 8, 52, 55) with their pause and fire frames; states `gsActivating`, `gsReady`, `gsFiring`, `gsDropping`. A weapon fires when the gun reaches a fire frame (`geFire` → `TQuakeWorld.FireGun`) and refires once the firing frames have played (blaster 0.5 s, shotgun 1.2 s); switching puts the old weapon away and raises the new one (`geChangeWeapon` makes `PendingSlot` current); the shotgun's frame 9 only ejects, the machinegun alternates frames 4 / 5 while held, the chaingun spins 1 / 2 / 3 bullets a frame and loops frames 15–21 (`geChaingunUp` / `Down`, loop sound), the hyperblaster loops 6–11 with its bolt circling the muzzle, the BFG flashes on frame 9 (`geBfgFlash`) and fires the ball on 17, hand grenades pull the pin on frame 5, cook on frame 11 (3.2 s fuse, `hgrenc1b` loop) and are thrown on 12 or go off in the hand (`geGrenadeThrow` / `geGrenadeBlowUp`). Without ammo it clicks at most once a second (`geNoAmmo`) and `NoAmmoWeaponChange` picks the best weapon with ammo. `FireWeapon` (called every frame while fire is held) sets `Attack`; a new press is latched (a tap fires even mid-switch, when the gun gets ready) and thinks at once (Quake 2 `weapon_thunk`), restarting the frame clock. `TQuakeMd2Instance.ShowFrames` draws the view model between `OldFrame` and `Frame` (`FrameLerp`). Idle frames pause at random like Quake 2 (`RandomPauses`, off in autotests so screenshots repeat). The gun's `LoopSound` goes through the loop mixer at the listener.
- **Props** (`TQuakeProp`): `misc_explobox` (10 health, `dmg`+40 radius explosion, chain reactions), `misc_banner` (looping animation), `misc_deadsoldier` (pose from spawnflags), `misc_satellite_dish` (animates when used), `misc_strogg_ship` (hidden until used, then flies its `path_corner`s), `misc_gib_head`.
- **Timers and effects**: `func_timer` (`wait` ± `random`, START_ON, toggled by use), `target_splash` (particle colours by `sounds`), `target_laser` (`TCastleBox` beam stretched to the first wall hit, damages the player in it, toggled by use).
- **Help computer / intermission**: `target_help` fills the primary / secondary objectives; on `target_changelevel` the view moves the camera to `info_player_intermission`, freezes the world and shows the help-computer layout as a mission summary until a key press.
- **Damage**: armor absorbs `protection × damage` (jacket 0.3, combat 0.6, body 0.8), quad damage ×4, invulnerability; death restarts the level.
- **Monsters**: idle → sight (throttled `LineOfSight`) → chase (`TCastleTransform.Move` with `CollisionSphereRadius`, floor via `TCastleTransform.Height`) → attack (callback into the world: melee, hitscan, pellets, rail, blaster bolt, rocket, grenade) → pain → death / gib. `ResolveTargets` sorts `target` like Quake 2's `monster_start_go`: a `path_corner` becomes `MoveTarget` (idle `Patrol` at 40% speed with the walk animation, `wait` pauses, `pathtarget` fires, `wait -1` stops), a `point_combat` becomes `CombatTarget` (`Alert` turns it into `GoalEntity`: run there without attacking, follow its `target` chain, spawnflag 1 sets `HoldGround`), anything else is the `DeathTarget` fired on death. Player-clip brushes are switched off while monsters move.
- **Attack frames** (unit `QuakeMonsterAttacks`): `MonsterAttackSeqs(ClassName)` lists a monster's Quake 2 attack sequences (from the `mframe_t` tables of `m_soldier.c`, `m_infantry.c`, `m_gunner.c`, `m_berserk.c`, `m_flyer.c`, `m_parasite.c`, `m_tank.c`): first model frame and length, fire frames, kind and per-shot damage (with `RepeatDamage` / `DamageRandom`), sound, a burst frame held for `HoldMin`..`HoldMax` more frames while the player is visible (`AI_HOLD_FRAME`: machinegun soldier 3–10, infantry 3–18) and a refire loop (`LoopStart`..`LoopEnd`, `LoopChance`: the gunner's chaingun). `ChooseAttackSeq` picks by range like the Quake 2 attack functions (`auMelee` under 80 units, `auRanged` beyond, `auAny` both). `TMonsterAttack` plays one at 10 frames a second and calls `OnFire` on fire frames; `TQuakeMonster.StartAttackSeq` resolves the first frame by name in the model, draws `Model.ShowFrames(old, current, lerp)`, and `AttackSeqFire` sets `AttackKind` / `AttackDamage` / `AttackBullets` / `AttackReach` before `OnAttack` (`TQuakeWorld.MonsterAttack` fires one bullet per hitscan call). Pain, ducking and death stop the sequence (`SetState`). Monsters without a table keep the generic attack (one shot partway through the attack animation, `AttackFirePoint`). The unit tests check every table against the demo models' frame names and the timings. Soldiers follow `m_soldier.c` closely: attack1 / attack2 with the refire functions (`lcRefire`: back to the shot in melee range, or half the time on nightmare; otherwise the light soldier jumps over its cocking frames, `SkipFrame`), the machinegun soldier only attack4, and attack3 (duck and shoot, `auDodge`, crouched on `DuckFrom`..`DuckTo`) from `Dodge` on medium (1/3 of dodges) and hard (2/3), refiring while the dodge pause (`PauseLeft`, Quake 2's `pausetime`) has more than 0.4 s left. The tank also has `attack_chain` (19 machinegun bullets of 20), and fires rockets only beyond 250 units like `tank_attack` (`MinDist`; closer it picks blast or chain). The flyer slashes in melee range (`flyer_melee`: blades out on attak101..106, wing strikes of 5 on attak109 / attak114, the loop attak107..118 repeated 80 % of the time while in melee range, `lcMelee`). Melee hits of monsters with a ranged attack reach `MELEE_DISTANCE` (+24), like `fire_hit`; melee monsters keep their own reach.
- **Walk and run frames** (unit `QuakeMonsterMoves`): `MonsterMoveSeq(ClassName, Run)` holds each demo monster's looping walk / run `mframe_t` table (first model frame and the `ai_walk` / `ai_run` distance of every frame: soldier run03..08, infantry run01..08, gunner run01..08, berserk run1..6, the flyer on its stand frames at 10 / 5, parasite run03..09, tank walk05..20; walking uses `soldier_move_walk2` and the berserk's first 11 distances, as Quake 2 plays them). `TQuakeMonster.AdvanceMove` plays the run loop while chasing (`msChase`) and the walk loop while patrolling at 10 frames a second (`TMonsterMoveAnim`, drawn with `ShowFrames`), and `TryMove` moves at the current frame's distance × 10 per second instead of the type's constant `Speed` (kept for monsters without a table or model). So the pace is Quake 2's: soldiers 122, gunners 121, infantry 144, berserkers 192, parasites 254, flyers 100, tanks 47 units a second running, with the feet in step.
- **Perception** (Quake 2 `FindTarget`): a monster notices the player it can see within 1000 units: always within 80 (melee range), within 500 when he is in front of it (cos > 0.3) or fired in the last second (`PlayerShowHostile`, Quake 2 `show_hostile`), within 1000 only in front (`TQuakeMonster.WouldNotice`). Noise (`TQuakeWorld.PlayerNoise`: weapon fire, the player's explosions) wakes monsters within 1000 units that can hear it: in the PHS of the noise's cluster and in an area connected through open portals (`TQuakeGeometry.CanHear`, PHS rows decompressed by `TQuakeBsp.ClusterPHS`); AMBUSH monsters (spawnflag 1, most of the demo's) must also see it. When a monster finds the player (`OnFoundTarget`), non-ambush monsters that would notice it and see it join in on the next frame (`ProcessSightEntities`, Quake 2 `level.sight_entity`). TRIGGER_SPAWN monsters (spawnflag 2) are `Dormant` (no transform, collisions, damage or AI) until their targetname is used; then they appear and, unless AMBUSH, hunt the player (`monster_triggered_spawn`). `Dormant` is kept in savegames.
- **Pursuit** (Quake 2 `p_trail.c`, `ai_run`): `TQuakeWorld.UpdatePlayerTrail` (every 0.1 s) drops a spot at the player's origin when the newest spot is no longer in his line of sight, keeping the last 8 (`TQuakePlayerTrail`). A hunting monster that can't see the player runs to where it saw him last (`FLastSighting`), then to the oldest trail spot newer than the one it reached before (`PursuitGoal`), spot by spot, which leads it around corners instead of into the wall between them; with no spot left it heads for the player again. Flyers keep heading straight for him. The trail isn't saved in savegames.
- **Dodging** (Quake 2 `check_dodge`): when the player fires a blaster bolt, rocket or BFG ball (`SpawnProjectile`), `TQuakeWorld.CheckDodge` ray casts along the shot; if it reaches a living monster facing the player (cos > 0.3), `TQuakeMonster.Dodge(eta)` runs (on easy only a quarter of the time). Soldiers, infantry, gunners, medics and iron maidens (the monsters with `monsterinfo.dodge`) then duck a quarter of the time: state `msDuck`, the `duck` animation stretched over `eta + 0.3` s (0.4–1.5 s). Shots use `ShotRayCast`, which ignores hits on a ducking monster above 8 units below its origin (Quake 2 ducks to `maxs.z = -8`), so level shots fly over it.

---

Full-game entities the demo maps don't use are tested by spawning them (`spawn` console command, `TQuakeWorld.SpawnEntity` = the per-entity body of `SpawnEntities`): `misc_viper` flies its `path_corner`s like `misc_strogg_ship`; `misc_viper_bomb` drops with the flying viper's velocity under gravity (`UpdateFallingProps`, traced with `MASK_SHOT`) and explodes for `dmg` (1000) on impact; `misc_bigviper` and the easter-egg tank / chick poses are static models (`AnimFirst`..`AnimLast` frame loops, like `misc_blackhole`, which disappears when used); `target_blaster` fires a blaster bolt along its movedir; `target_earthquake` shoves a grounded player every 0.1 s for `count` seconds (`target_earthquake_think`: ±150 sideways, `speed` / 2 up) with `quake.wav` every 0.5 s; `target_spawner` spawns an entity of class `target` at its origin and telefrags what is there; `func_killbox` (invisible, not solid) and `KillBox` telefrag everything in the box; `trigger_gravity` sets the player's gravity multiplier until the next level (`SetPlayerGravity`).

Skies turn like Quake 2's `R_SetSky`: worldspawn `skyrotate` (degrees a second) around `skyaxis` (Quake coordinates; a map without it turns around the vertical) sets `TCastleBackground.Rotation` every frame from the level time (`TQuakeMap.UpdateSkyRotation`; the Quake -> CGE axis change is a proper rotation, so the angle keeps its sign). The `sky` console command swaps the sky and its rotation until the next map. Currents follow `PM_AddCurrents`: `CONTENTS_CURRENT_0 / 90 / 180 / 270 / UP / DOWN` in the water at the player's feet add 400 (200 when wading on the ground) along that direction to the wished velocity, and the same bits on the brush the player stands on (a `func_conveyor` or a world brush; the ground trace's `Contents`) add 100, in both the water and the air / ground moves (`PMCurrentVelocity`).

Gibs follow `ThrowGib` / `ThrowHead`: `MonsterGibs` holds each demo monster's pieces from its `*_die` function (soldiers: 3 `sm_meat`, `chest`, `head2`; infantry, gunner, berserk, parasite: bones, meat, `head2`; tank: meat, 4 `sm_metal`, `chest`, a `gear` head, metallic pieces bouncing) and `gib_health` (soldiers -30, infantry -40, parasite / flyer -50, berserk -60, gunner -70, tank -200); a monster or its corpse at or below it is gibbed (`TQuakeMonster.Gib`, also when a door crushes it). `Particles.ThrowGibs` starts each piece at a random point of the body box with `GibVelocity` (100 * crandom sideways, 200 + 100 * random up, times 0.7 below 50 damage or 1.2, clipped to ±300 / 200..500) and a spin, gone after 10–20 s; `UpdateGibs` moves them under gravity on `GibTrace` (`TQuakeWorld.GibTraceMap`: a point trace against `CONTENTS_SOLID | CONTENTS_WINDOW`, so not monsters or the player) — organic pieces slide along walls and stop on floors with `misc/fhit3.wav` (`MOVETYPE_TOSS` + `gib_touch`), metal and barrel debris bounce (`MOVETYPE_BOUNCE`). The flyer explodes on death (`BecomeExplosion1`) instead of leaving a corpse.

Animated textures follow `R_TextureAnimation`: a face shows the texture `frame mod chain length` steps after its own one in the chain. The world's frame is the time × 2; a brush entity's comes from the client's `CL_AddPacketEntities` rules (`TQuakeMover.TexFrame`): `EF_ANIM_ALL` (time × 2) or `EF_ANIM_ALLFAST` (time × 10) for doors / rotating doors (spawnflags 16 / 64), walls and explosives (8 / 16) and rotating brushes (64 / 128); buttons have no effect until pressed (frame 0), `EF_ANIM23` (frames 2, 3) from reaching the top (`button_wait`) and `EF_ANIM01` (0, 1) once back (`button_done`); everything else frame 0.

Clocks and displays follow `g_misc.c`: a `target_character` is a brush (drawn, like `func_*` brushes) whose texture frame is its character — 0–9, 10 for `-`, 11 for `:`, 12 blank (`TQuakeMover.CharFrame`); a `target_string` writes its message across the characters of its `team`, each taking the letter at its `count` (`CharacterFrame`). A `func_clock` thinks once a second (`UpdateClocks`): TIMER_UP (1) counts from 0 to `count` (an hour by default), TIMER_DOWN (2) from `count` to 0, neither shows the time of day; it formats the value by `style` (`ClockText`: `%2i`, `%2i:%02i`, `%2i:%02i:%02i`) into its target_string and uses it, and at the end fires `pathtarget`, stopping unless MULTI_USE (8), in which case it resets (and waits for a use again with START_OFF, 4).

Model lighting follows `R_LightPoint`: `TQuakeBsp.LightPointStyles` traces 2048 units down to the first lit face and returns its lightmap texel for each of its (up to 4) styles — the face's lightmaps are consecutive blocks of `3 × width × height` bytes — and `TQuakeLighting.SampleLight` sums them scaled by the styles' current values (`StyleValue`: patterns, switches, ramps), doubles the result like the world's overbright, keeps a 0.18 floor and adds dynamic lights. Monsters, items and props re-sample every 0.1 s (Quake 2 relights entities every server frame), so they flicker and darken with the world.

Medics revive the dead like `m_medic.c`: `UpdateMedics` stands in for `medic_FindDeadMonster` (once a second, also while the medic is fighting): a dead (finished dying), not gibbed monster within 1024 units that the medic can see and no other medic has claimed, the one with the most max health. The medic then only walks to it (`UpdateMedic`, AI_MEDIC) and, within 250 units in sight (the cable reaches 400), plays its cable for a second (`attack33` .. `attack43`) before `Revive` (ED_CallSpawn: full health, standing, collidable again, alerted at the player through FoundTarget) and `OnRevived` (monster_start counts it in the level's monsters again). A patient that gets gibbed or revived meanwhile frees the medic.

Turrets follow `g_turret.c` (pure math in `QuakeTurret`, tested by the unit tests): `turret_breach` and `turret_base` are movers of kind `mkTurret`, drawn with their Quake angles (`TurretPitch` / `TurretYaw` → `TurretRotation`; console-spawned ones without a `*N` model are grey boxes from `mins` / `maxs` with no brushes, `AddBoxMover`, which traces skip). `TQuakeWorld.UpdateTurrets` links each breach once (`LinkTurret`: the muzzle offset from its `target`, the bases of its `team`) and each `turret_driver` (an infantry with `TurretDriver`: no movement, attacks, pain or dodging; gib health 0) to the breach its `target` names, then every frame does `turret_driver_think` (aim with `QuakeVecToAngles` at the player's eye while the driver sees him; fire when `3 - skill` seconds have passed since he was (re)acquired, then every `reaction + 1` s) and `turret_breach_think` (`TurretClampAngles`, `TurretStep` at `speed` degrees a second, the bases' yaw follows, the driver is placed with `TurretDriverOrigin` and tilted with the gun). `TurretFire` launches a rocket from `TurretMuzzle` (100–150 damage and splash, radius 150, speed 550 + 50 × skill). When the driver dies the breach levels (`move_angles[PITCH] = 0`) and stops firing. Turrets only push the player (`PushPlayerByMovers`) and deal their `dmg` (10) when blocked; their angles are saved with the movers.

The player dies like `player_die`: below -40 health the body is gibbed (`misc/udeath.wav`, 4 `sm_meat` through `Particles.ThrowGibs`, the view in the head), otherwise a death sound; the view weapon disappears (`gunindex = 0`). `TViewPlay.UpdateDeathView` then moves the camera like the dead pmove and view angles: over 0.3 s the eye drops from origin + 22 to origin + 8 (`PM_DEAD`), or to the floor + 8 when gibbed (`PM_GIB`), and the view turns to the killer (`LookAtKiller`, from the damage's origin), pitches -15 and rolls 40. The `kill` console command is Quake 2's suicide: health 0, so no gibs, and god mode doesn't stop it.

## 6c. Random levels and the level editor

A level is a `TQuakeLevel` (unit `QuakeLevel`): a grid of 64-unit cells. Each cell is a wall, or open space with its own floor and ceiling height (on 16-unit steps), a texture theme (`LevelThemes`: floor, wall, ceiling, step and light-panel WALs of the demo PAK) and maybe a sky ceiling. The level also holds Quake 2 entities (`TLevelEntity`: class, origin, angle, keys). It saves to JSON: one string per row (`#` or `floor,ceil,theme[,s]`), then the entities. Entities standing on a cell get Quake 2's origin heights plus 1 (`EntityFloorOffset`: monsters / player 25, items 17), because a box touching the floor would start its traces in solid.

`QuakeBspBuilder.BuildLevelBsp` compiles it into an IBSP v38 file, playing the parts of qbsp, qrad and qvis:
- **Tree:** k-d splits on cell boundaries (longer side in half) until a rectangle is uniform (wall, floor, ceiling, sky, theme). An open rectangle becomes a node on its ceiling plane (solid leaf above) over a node on its floor plane (empty leaf above, solid leaf below). Node planes have positive axial normals, because the trace code's axial shortcut assumes them. Leaf 0 is a dummy solid leaf, as Quake 2's `CM_LoadLeafs` requires.
- **Brushes:** one box brush per solid leaf. Brush sides facing the negative way use the "any axis" plane types. With these, `TQuakeCollision` (CM_BoxTrace) collides with exactly the walls, floors and ceilings.
- **Faces:** per open cell, its floor (on the floor node, so `R_LightPoint` finds it), its ceiling (on the ceiling node: sky texinfo with `SURF_SKY`, or the light panel over a light), and its walls. Walls face solid or higher / lower neighbours, like Doom's lower and upper sides, with steps in the theme's step texture. Walls are split every 256 units, and faces wind clockwise with Quake's texture axes. Each face is listed in its region's leaf.
- **Lightmaps:** sampled every 16 texels like `CalcSurfaceExtents`. Each sample adds qrad's linear point light for every `light` entity (intensity − distance, scaled by the angle), with shadows from rays through the grid. A little ambient light is added, more under the sky.
- **Visibility:** one cluster per empty leaf (and per water leaf), one area. Like qvis, but on the 2D grid: two regions see each other when a sight line joins sample points on their facing sides (every cell corner) without crossing a wall cell (`SightClear`, a grid walk with a slab test per wall cell). Walls are shrunk by 4 units on their open sides, so lines grazing a corner stay clear, but not along the seams between wall cells; heights and doors never block. Every error is on the visible side, and regions that touch always see each other. The PHS row of a cluster is the union of the PVS rows of the clusters it sees. Rows are run-length compressed like Quake 2's. On `rand7` (338 clusters) a cluster sees 23 % of the others; the pass takes about 0.2 s (`TBspBuildStats.VisPercent` / `VisMsec`, in the `Built` log line).
- **Water:** a region with water gets a third node on the water plane. Above it is the air leaf; below it is a `CONTENTS_WATER` leaf with its own cluster and a water brush (so both the leaves and the brushes report water). The surface is two warped, translucent faces (`SURF_WARP | SURF_TRANS33`, `e1u1/bluwter`, no lightmap), one facing up and one facing down, listed in both leaves.
- **Lifts and buttons:** lift cells with the same floor and top are a `func_plat` model (`BuildMoverGroups(True)`): a 16-unit slab with its top at `LiftTop`, built up, with `"height"` = top − floor + 2, so it starts down with its top hidden 2 units under the floor (no z-fighting). A button cell is a 24 × 24 × 40 pedestal (`BuildBoxModel`: six nodes around one solid leaf) spawned as `func_button` (angle −2 = down, lip 4, wait −1). It targets `switch<channel>`, and door groups of that channel get `targetname switch<channel>` and wait −1 (opened once, they stay open; no trigger field, so neither the player nor monsters open them by touch).
- **Doors:** each group of touching door cells with the same heights and channel becomes a brush model (`BuildMoverGroups(False)`). Its own small tree is solid from floor to ceiling inside the door cells and empty around them, with one brush per solid leaf. Its faces are the sides towards open cells plus the bottom, lit like the world. It is spawned as `func_door` (`model *N`, angle -1 = up, speed 100, wait 3, lip 8). The world stays open in door cells.

`RegisterLevelMap` adds the file to the PAKs in memory (`TQuakePak.AddMemoryFile`, `maps/<name>.bsp`).

`QuakeBsp.MissingMapHook` (set by `QuakeLevelGen`) builds maps on demand when they aren't in the PAKs: `rand<seed>` is generated, and `<name>` is the editor's `castle-config:/levels/<name>.json`. So `map rand42`, saved games, restarts, level exits and `TQuakeMap.MapName` in the CGE editor all work with them.

`QuakeLevelGen.GenerateLevel(seed)` uses its own xorshift generator, so the same seed gives the same level on every platform. It applies these rules:
- **Rooms:** up to 11 rooms, 4–8 cells or 9–13 for an arena, 3 cells apart.
- **Links:** a Prim minimum spanning tree plus about a third more links for loops.
- **Heights:** room floors assigned outward from the start, ±48 per link.
- **Corridors:** two cells wide, L-shaped, with one low ceiling (112–128) and at most one 16-unit step per cell.
- **Room features:** pillars every 3 cells in big rooms, a raised platform with a step ring, 22 % sky rooms with higher ceilings.
- **Secret:** a 3 × 3 room behind a 3-cell crawlway, with a quad or megahealth and a `trigger_once` → `target_secret` (box triggers through the `mins` / `maxs` keys).
- **Doors and pools:** 40 % of corridors get a door where they leave their first room, across both lanes. 30 % of rooms without a platform get a sunken pool: floor −64 and water up to −8, so the edge is a step above the water.
- **Lifts:** 20 % of links climb 96–144 units. A corridor with a climb of 80 or more (or one too steep for steps) gets a 2-cell lift beside the lower room and runs at the higher floor after it.
- **Exit switch:** the corridor cells at the exit room's entrances become doors of channel 1. A channel-1 button goes in a room between a quarter and 85 % of the way, at a cell reachable with those doors shut. Entrances with a lift or water skip the switch.
- **Reachability:** every open cell must be walkable from the start (steps ≤ 16, headroom ≥ 64, or swimming up to a ledge at most 16 above the water, as `PM_CheckWaterJump` allows; a lift cell counts at its floor and at its top). Unreachable cells are pulled towards a reachable neighbour, then walled up.
- **Lights:** over every room, every 4 cells.
- **Monsters:** none in the start room. The count grows with room area and depth. Soldiers come early, then enforcers, infantry and flyers, then gunners, berserkers, parasites, and the tank only in big rooms. 20 % wait in ambush, and some extras have spawnflag 256 (not on easy).
- **Items:** the 7 weapons in order of depth, with ammo for them after. Health and armor follow the fights, plus barrels.
- **Exit:** the deepest room holds a `trigger_once` → `target_changelevel` to `rand<seed+1>`.

The unit tests check 12 seeds for rooms, monsters and reachability, and that the same seed gives the same level. CI generates `rand7`, stands on its floor and exits to `rand8`.

`TQuakeLevelEditor` (unit `QuakeLevelEditor`, a registered `TCastleUserInterface`) is the 2D editor. `TViewPlay.OpenEditor` puts it over the game and freezes the world while it is open.
- **Layout:** a toolbar with tools and commands, the grid and an entity palette. Cells are tinted by theme, brighter for higher floors and bluish under the sky. Entities are dots with a letter and a facing tick.
- **Strokes:** each tool changes a cell once per stroke, and fast drags paint every cell in between. Undo keeps up to 40 JSON snapshots.
- **Commands:** *Generate* loads `GenerateLevel(random seed)` under the editor's name. *Save* / *Load* use `LevelFileUrl`. *Play* saves, compiles and loads `*<name>` (a new unit). *Export* writes the `.bsp` through `UrlSaveStream`.
- **Scripting:** the `editor` console command (`new`, `generate [seed]`, `save [name]`, `load <name>`, `play`, `export`, `close`, `name`, `tool`, `entity`, `brush`, `channel`, `lift`, `fill x0 y0 x1 y1`) drives it from demo scripts. CI also builds a level with a door and a pool: walking into the door opens it, and the player stands in the pool fully under water. Another CI level has a lift up to a balcony and a channel door: riding the lift lifts the player 128 units, and touching the button opens the door. CI paints a corridor with simulated mouse drags, places a soldier, saves, generates, reloads and plays.

## 6b. Savegames

`TQuakeWorld.SaveState` / `LoadState` write and read a `fpjson` object: player stats and inventory, then arrays per entity list (monsters, pickups, movers, props, triggers, lasers, speakers) in spawn order, plus `func_timer` / `trigger_counter` state keyed by BSP entity index and light styles 32–62. Loading reloads the map fresh and applies the state on top (`TQuakeMonster.RestoreState`, `TQuakeMover.ApplyPose`). The view adds the camera and stores the file with `UrlSaveStream('castle-config:/saves/<name>.json')`.

Projectiles in flight (kind, position, velocity, damage, splash, remaining life, owner monster index) and pending delayed events (seconds left, targetname or the BSP entity index for a delayed `target_explosion`) are saved too, so a quick save mid-fight restores exactly. The world clock restarts at 0 on load, hence the delays are stored relative. A level revisited in a unit (`IncludePlayer = False`) starts without projectiles and keeps the events scheduled at spawn (Quake 2's `ReadLevel` re-arms `target_crosslevel_target` that way).

`delay` follows Quake 2: an entity's `delay` postpones the use of its targets (`UseTargetsOf`, `G_UseTargets` for relays, `target_*`, `trigger_*`), and `target_explosion` delays its own blast (`use_target_explosion`).

## 7b. View feel (`TQuakePlayerMovement`)

Quake 2's `SV_CalcViewOffset` / `SV_CalcGunOffset` / `P_DamageFeedback`: every frame `TQuakePlayerMovement.Update` removes the previous frame's view effects from the camera (`ClearViewEffects`), runs pmove (`Move`), then applies new ones (`UpdateViewEffects`), so effects never change where the player is or what collides. Effects: eye bob (`bob_up` 0.005 × horizontal speed, at most 6 units, `bobtime` advancing 0.0625–0.25 per 0.1 s frame by speed), bob pitch / roll (`bob_pitch`, `bob_roll` 0.002, ×6 crouched), running pitch / roll (`run_pitch` 0.002, `run_roll` 0.005), the landing dip and nod (`fall_value` = landing delta / 2, at most 40, over 0.3 s, for deltas ≥ 15) and the damage kick (`DamageKick`, called by `TQuakeWorld.DamagePlayer`: kick = damage × 100 / health clamped to 50, split into pitch and roll by where the damage came from, over 0.5 s). Pitch is applied around the camera's right axis, then roll around the view direction, and undone in reverse. `GunAngles` (weapon bob and lag behind turning: 0.2 × the per-0.1 s angle change, clamped to 45°) goes to `TQuakeWorld.SetGunAngles`, which rotates the view weapon in the weapon viewport. Code that aims, uses or saves the view reads `AimPosition` / `AimDirection` (view without effects); code that moves the camera directly calls `ClearViewEffects` first, and `ResetVelocity` (after `PlaceCamera`) forgets them. *Options → View Bob* (`Settings.ViewBob`) turns it all off.

## 8. Options and skill

`QuakeGamepad` maps game controllers (CGE `Controllers`, initialized at startup except in autotests) to the same inputs. Its functions are pure so the unit tests check them: `ApplyDeadZone` (radial, 0.2, rescaled so output starts at 0), `StickToMove`, `StickToLook` (squared response, 160 / 120 degrees per second yaw / pitch at full deflection, times the mouse sensitivity option, inverted with *Invert Mouse*), `StickToArrow` / `GamepadMenuKey` / `GamepadMenuEvent` for menus and `GamepadWeaponCycle`. `ReadGamepads` sums every connected controller plus `VirtualGamepad` (set by the `GP:` demo action, since CI has no device). `TViewPlay.UpdateMovementInput` adds the sticks to the key movement and passes look as `TQuakePlayerMovement.InputYaw` / `InputPitch`, which `ApplyTurn` applies after `ClearViewEffects` and before pmove (pitch clamped to ±89°); the right trigger fires in `Update`. Buttons arrive as `itGameController` press events in `TViewPlay.Press` (use, grenades, weapon cycle, help, menu); while the menu is open they are translated to arrow / Enter / Escape key events, and `TQuakeMenu.Update` turns the left stick into repeating arrows.

`QuakeTouch` adds on-screen controls for touch screens (`TouchControlsWanted`: `ApplicationProperties.TouchDevice` on Android / iOS, or `--touch`). `TQuakeTouchControls` is a full-size UI in front of the viewport; each finger gets a role on press: a button (FIRE, JUMP, DUCK held; USE, WPN, MENU call `OnUse` / `OnNextWeapon` / `OnMenu`), the move stick (first touch on the left 40 %: base where the thumb landed, `TouchStickVector` clamps the offset to the radius, 12 % of the screen height) or look (other touches: drag deltas accumulate until `TakeLook`). `TViewPlay.UpdateMovementInput` adds the stick to the movement and the look to `InputYaw` / `InputPitch`, so touch shares the pmove path with keys and gamepads; the controls hide (and drop their fingers) under the menu, console, intermission and death. `TQuakeMenu.Press` handles taps (`ItemAt` uses `Render`'s row layout: a tap selects, a tap on the selected row runs `AdjustOption` by screen half or `ExecuteSelection`). The PAK loads through CGE's `Download`, which reads APK assets, so Android needs no data changes.

`QuakeSettings` holds the player options (`TQuakeSettings`: mouse sensitivity as a multiplier of CGE's default, invert, horizontal FOV, sound / music volume, a key per `TQuakeAction`, last chosen skill), loaded from and saved to CGE's `UserConfig` (`quake2/...` keys, only non-default values stored). `TQuakeMenu` edits them on the *Options* and *Controls* pages (Left / Right change values, Enter on a control waits for a key; binding a used key swaps the two) and raises `maSettingsChanged`, on which `TViewPlay.ApplySettings` sets `TCastleWalkNavigation` sensitivity / `InvertVerticalMouseLook`, the camera's `Perspective.FieldOfView` and the sound engine volumes. `GameSkill` is Quake 2's latched `skill`: set by *Single Player*, the `skill` console command (next map) and savegames (before the map loads, since entities are matched by spawn order). It selects the spawnflag that removes entities (`SPAWNFLAG_NOT_EASY` / `_MEDIUM` / `_HARD`), halves player damage on easy (`T_Damage`), scales the time between monster attacks (`M_CheckAttack`'s attack chance) and disables pain reactions on nightmare.

Phones are small: with CGE's `EncloseReferenceSize` scaling (1600 × 900) a menu row is 4 % of the screen height everywhere, about 3 mm on a phone. `InterfaceScale` (Settings.InterfaceSize: Auto, Small 0.8, Normal 1, Large 1.4, Huge 1.75; Auto is 1.75 when `TouchInterface`, set at startup from `TouchControlsWanted`) multiplies `UIScale` in the menu (font size, row height, the number of rows that fit above the hint with "..." when more exist; `RowLayout` is shared by `Render` and the tap test `ItemAt`, which accepts the whole row height), the console, the HUD labels (`FontSize`, set in `Update`) and the pickup text (centered on touch screens, where the buttons cover the bottom right). The help computer's text grows with its picture (`UIScale`), and the touch button labels with the buttons (2.6 % of the screen height).

## 9. Automated testing

`--map-report <file.md>` runs like an autotest (default options) but loads every map of the PAKs through `TQuakeWorld.LoadMap` (`*map`, a fresh unit each) and writes a Markdown report (`QuakeMapReport.TMapReport`): load time, faces, entities, monsters, items, and the entity classes the game doesn't handle (`EntitySupport`: supported = spawned, used by targets, drawn or used as markers; partial = generic monster AI, `func_*` brushes without their behaviour, `func_wall` toggles; unsupported = the rest), counting only entities spawned on the current skill. CI runs it on the demo PAK and fails if an unsupported class appears.

`--autotest <map> <prefix> --demo "<script>"` loads a map, runs the script (see README) and exits after a final screenshot. Screenshots log the FPS and camera position, `V` logs every mover's state, and `N:` / `I:` / `D:` place the camera on a floor near a monster / item / mover, which makes visual regression checks of AI, pickups and movers possible without a human player.

`record <name>` turns a play session into such a script (`QuakeRecord`). It starts a new unit with `ResetStats` (autotests start fresh), then `TViewPlay.SampleRecording` feeds `TQuakeRecorder.Sample` at the end of each `Update` with the aim (Quake yaw / pitch), `PlayerMovement.InputForward` / `InputSide`, jump / crouch and firing; the recorder writes an `IN:` line when a held input changes (at once), the view turns (at most every 0.05 s) or the player has moved for 0.5 s, each with the position. Instant actions arrive through `RecordCommand` as an `IN` that only waits plus the command (`C:slot`, `U`, `F`, `X`, `O:console command`, `B:enter` to leave an intermission). `IN` waits on a script clock (`FDemoClock`, all frame times since the script or its last `L:`) rather than counting frames, skips INs that are already due (keeping their jump / fire taps), holds the inputs until the next one, and corrects the player's position when it drifted more than 2 units and the recorded spot is free, so replays at another frame rate end where the recording did (CI: within 8 units; typically < 1).
